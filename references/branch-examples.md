# 减少误解的措辞对照

仅在编写对应节点时参考。示例数值、路径与命令不是实际实验配置，不应原样注入任何批次。

## 工程入口

含糊写法：搭好环境、build 新镜像，参照上批提交；`batch.image=<新镜像>`；入口与集群编排可沿用上批实现，按本批矩阵改写。

应改为：写出已确认的工作目录、环境进入命令、代码部署方式、提交命令和日志位置，命令可直接复制。代码经挂载进入且依赖未变，就按已成功的方式用原镜像并写出镜像名加 tag；代码打入镜像，就给确定的构建配方与推送命令。拿不到镜像名、构建配方或提交入口时，编写者先定向获取事实，或写明执行侧自己保存的上批实际命令记录文件的路径，要求照用。不让执行者以开放式探索填补缺口，不虚构命令。

## 运行位置、并发与内存

含糊写法：在本地跑即可；估计每格的内存，不要超过机器容量；OOM 了视情况重试；集群不可用时可在本机运行。

应改为，全部变成数字和命令，执行者不判断：训练单元的 cmd 是 `sbatch --wait --partition gpu-a100 jobs/train.sh s158 101`，done_file 是 `out/train/s158_101/final.pt`；仿真单元的 cmd 是 `python sim.py --case s158_e090`，done_file 是 `out/sim/s158_e090/RESULT.json`。启动命令 `python run_units.py run --units units.jsonl --concurrency 4 --retries 2 --retry-sleep 60 --min-free-gb 8 --detach`，其中 4 来自上批记录的单格峰值 2.5 GB 与机器 32 GB，8 是留给系统的余量。内存不足时脚本自己等待，不启动新单元；单元失败两次后隔离，整批继续。执行者不改这些数字，也不会遇到“在哪跑”的选择题。

## 授权与停点

含糊写法：预检通过后汇报，待确认后开跑；完成 F0 冻结后等待研究侧放行。

应改为：预检是步骤表里的一行，`OK` → 下一步，其他情况 → 记录并到下一步或隔离。只有用户本批明确要求的停点才写成一行：命令 `python run_units.py stop`，去向“本批到此为止；用户发出继续指令后从标为‘恢复’的步骤重新开始”。

## 用户给的时间窗口

含糊写法：本批 8 小时，到点收口；准备起 120 分钟硬截止，不越时补算；最多 10 次模型启动。

应改为：预计 6 到 9 小时，写在「本批做什么」并标“估计”，不出现在任何步骤的去向里。只有用户明说“到点必须停”时，才在等待步前加一行：`python checks/past_deadline.py` 输出 `PAST` → 运行 `python run_units.py stop`，到收口等待步（`status --wait 540`：`RUNNING` → 本步；其他 → 汇总步）；输出 `NOT_YET` → 等待步。启动次数不设上限。

## 等待

含糊写法：每 10 分钟看一次日志，确认作业还在跑；长时间没进展再处理。

应改为：等待步只有一条命令 `python run_units.py status --units units.jsonl --wait 540`；`RUNNING` → 等待步；`ALL_TERMINAL` → 汇总步；`RUNNER_STALE`、`NOT_RUNNING`、`NO_STATE` → 启动步。没有“确认”“没进展”这类判断，等待时长由命令自己控制。

## 中间交付

含糊写法：首批 45 条轨迹交付后等待研究侧反馈再继续。

应改为：首批 45 条轨迹是 units.jsonl 里排在最前的 45 行，它们的产物自然先落盘，汇总脚本把它们标 preliminary。步骤表不因此多一步，更不等待。

## 新增实现

含糊写法：实现新的损失函数，检查无误后执行。

应改为一行：命令“按规格 §4.2 在 `src/losses.py` 实现 `margin_loss(pred, target, tau)`，然后运行 `python checks/fx_margin_loss.py`”；看什么：标准输出末行；`OK` → 下一步；其他情况：把输出写入 PROGRESS.md，标本步 ISOLATED，到下一个不依赖它的步骤；依赖它的单元由 requires 自动隔离。算例只覆盖对应语义，不据此宣称整批科学正确；已可靠的旧函数不重复实现。

## 检查的写法

含糊写法：核对数据加载正确；验证模型身份；确认结果合理。

应改为：`python checks/inputs.py --case s158_e090` 打印 `OK` 或 `MISMATCH rows=998 expected=1000`；`OK` → 下一步；其他情况 → 记录、标 ISOLATED、到步骤 N。检查脚本由编写者写，只打印一行固定字符串；不单列审核步骤，不要求汇报。

## 局部失败与依赖

A 使用既有模型，B 训练新模型，C 对 B 的检查点评价。写法：C 的 requires 是 B 的 done_file；B 被隔离则 C 由脚本自动隔离，A 不受影响。不能一边写“仅阻断依赖单元”，一边写“A、B、C 全部检查通过后才统一启动”。

## 重试

含糊写法：同一错误不要重试；瞬态错误可以多试几次；最多 3 次尝试，超过则停止本批。

应改为：`--retries 2 --retry-sleep 60`，失败两次后隔离该单元，整批继续；抢占频繁的集群分区写 `--retries 6 --retry-sleep 300`。执行者不判断错误类型，数字由编写者定。不写全批停止条件。

## 不理想结果与运行错误

损失很高、指标为零、对照胜出，可能是有效科学结果：按原定义保存，继续既定单元。不为改善结果延训、换种子或提前结束比较。

NaN、梯度断开、加载错模型，可能使计算失去原定义：规格里写明数值处理规则，单元脚本按规则处理或以非零退出码结束，由运行脚本隔离。不把这些当普通负结果，也不以“不中断”为由静默切换目标或填零。

## 缺项与分母

例：规定三个种子，每个种子对四个 case 求均值，再对三个种子均值求平均。当前一个种子的一个 case 缺失。

仍保存已有的逐 case 结果，但该种子的完整均值与三种子总均值都记为缺项并列出缺失 case；不悄悄按已有样本求一个同名最终均值。可展示的部分统计必须预先定义并标为部分结果。汇总脚本按这条规则实现，执行者不做判断。

## 阈值等号与未计算

例：规则为误差 <= 0.01 时满足。误差为 0.01 为 true；0.0101 为 false；输入未产生时为 null 并附原因，不能默认为 false。数值容差另有定义时依其唯一配置执行。另一个指标未达标，不应导致这个指标不计算；除非其自身定义明确不适用。

## 长时间运行与恢复

预计数小时不构成终止规则。训练步数和矩阵按原设计完成，不随运行速度增减；不写“超时则减采样数、减样本”之类的降级规则。中断后重新进入，恢复步的 status 命令指向启动步，脚本按 done_file 跳过已完成单元；训练单元的 cmd 自身必须能从检查点续跑（含优化器与随机状态），否则在规格里写明重跑规则。只有末尾权重的模型文件不是完整训练恢复点，不冒充精确续跑。

## 跨批引用

含糊写法：环境种子同 claim 批 §2.1；GAE 实现见 9 月批 nahum_train.py 第 254 至 282 行。

应改为：在本目录规格文件写出 `env_seed(s, e, L)` 的完整定义与一个算例；复用代码写成执行侧可访问的直达路径与调用点，例如 `/workspace/outputs/runs/CLAIM-V1/package/common.py` 中的 `seed_ns`，并写明参数与返回值。执行者不需要打开任何别的批次的手册。
