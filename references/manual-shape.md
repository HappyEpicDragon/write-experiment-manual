# 手册骨架

目录里的文件按角色分；项目约定有固定文件名时沿用名字，角色与内容不变。不为凑数拆文件，也不在多个文件里重复维护同一数值。最终文件不留待填提示、尖括号或“待补”。

| 角色 | 默认文件 | 内容 |
|---|---|---|
| 入口 | `README.md` | 六节固定：执行约定、本批做什么、环境与入口、运行机制、步骤表、交付清单。执行者一次读完，一般 100 到 250 行 |
| 规格 | `PROTOCOL.json` 或 `SPEC.md` | 矩阵、数值参数、数学定义、指标、随机流、算例；数值只在这里维护 |
| 单元清单 | `units.jsonl` | 每行一个单元：id、cmd、done_file、requires；大矩阵由 `make_units.py` 从规格展开生成，脚本只做展开 |
| 运行脚本 | `run_units.py` | 从本技能 `assets/` 原样复制，不改；仓库已有满足 [运行脚本说明](runner.md) 四条的入口时可不带 |
| 检查脚本 | `checks/` | 算例与核对命令，每个只打印一行固定字符串，如 `OK` 或 `MISMATCH <说明>` |
| 启动提示词 | `LAUNCH_PROMPT.md` | 用户粘贴给执行侧的第一条消息，模板见 [执行侧固定块](executor-preamble.md) |

## 入口文件的六节

节名固定，因为「执行约定」块按节名引用。

### 0 执行约定

原样复制 [执行侧固定块](executor-preamble.md) 中的块，不改措辞、不删条目、不加条目。

### 1 本批做什么

3 到 8 句：回答什么问题、比较什么、矩阵规模、输出交给谁。目的与对照写到足以避免误做即可。假说如何改变研究判断属于研究侧，可放在规格里；入口只说实验侧交付数值与机械标签。预计耗时写在这里并标“估计”。不写历史路线、设计争论、作者侧检查记录。

### 2 环境与入口

来自最近一次成功运行的事实，逐条写死，供步骤表和 units.jsonl 引用：

1. 工作目录，绝对路径；步骤表的命令都从这里运行。
2. 进入运行环境的命令：conda、pixi、venv、容器或镜像名加 tag。
3. 代码如何进入运行环境：挂载、同步或打入镜像；本批是否需要构建；构建命令。
4. 单元的启动命令形态：本机直接运行，或阻塞式集群提交（`sbatch --wait`、`kubectl wait` 之类）；这决定 units.jsonl 里 cmd 的写法。
5. 日志位置；首条有效日志长什么样。
6. 产物根目录与本批输出目录；每个单元 done_file 的命名规则。
7. 凭据与配额从哪里取：引用既有位置或平台机制，不写秘密。

命令可直接复制运行；变量给确定值或无歧义的取值规则。复用代码写到文件、函数或 CLI 与参数；父批资产写执行侧可访问的路径。不出现尖括号、“按上批”“参照上次”“自行配置”。

拿不到某项事实时不猜命令：先定向向用户索要；或者写明执行侧自己保存的上批实际命令记录文件的路径，要求“照该文件的命令使用，不另行设计”。仍不能确定的部分在本节末尾列为“本批不可执行的部分”，其余部分照常可执行。

### 3 运行机制

写明运行脚本是哪一个（仓库已有入口，或本目录的 `run_units.py`），以及全部数字和来源：

| 项 | 写法 |
|---|---|
| 启动命令 | 完整一行，含 `--detach` 或等价的后台方式 |
| 并发 | 一个整数；来源是上批记录，或机器容量除以单元峰值内存；没有记录写 1 |
| 每单元重试次数与间隔 | 两个整数；本机写 2 和 60；抢占频繁的集群分区可以写大 |
| 内存等待阈值 | 本机单元写一个 GB 数（`--min-free-gb`）并写来源；集群单元写 0 |
| 单元峰值内存与显存 | 上批记录；没有就写“冒烟步测量”，并在冒烟步的命令里带上测量 |
| 状态命令 | `python run_units.py status --units units.jsonl --wait 540` 这类阻塞命令 |
| 恢复命令 | 与启动命令相同，脚本按 done_file 跳过已完成单元 |
| PROGRESS.md 位置 | 本批输出目录根 |

这些数字由编写者定，执行者不改。真实平台限制（GPU 数、分区、磁盘、作业时长上限、共享节点规则）在这里换算成上面的数字，不另写一节让执行者去遵守。

### 4 步骤表

入口文件的主体，执行者只读这张表。每行五列：

| 编号 | 命令 | 看什么 | 输出 → 下一步 | 其他情况 |
|---|---|---|---|---|

- 命令：原样可运行的一行。实现步写“按规格 §X 实现 `文件::函数`，然后运行 `python checks/fx_xxx.py`”。
- 看什么：命令标准输出的末行，或一个文件是否存在。
- 输出 → 下一步：一个或几个固定字符串，各对应一个步骤编号。
- 其他情况：具体动作加去向。默认写法“把命令与输出写入 PROGRESS.md，标本步 ISOLATED，到步骤 N”，N 是下一个不依赖本步的步骤。

必含的步骤：

| 步 | 命令 | 输出 → 下一步 |
|---|---|---|
| 恢复（标“恢复”） | `python run_units.py status --units units.jsonl` | `NO_STATE` → 冒烟步；`NOT_RUNNING`、`RUNNING`、`RUNNER_STALE` → 启动步；`ALL_TERMINAL` → 汇总步。重新进入会话时先做这一步 |
| 冒烟 | `python run_units.py run --units units.jsonl --only <首个单元 id> --retries 0`，或等价命令 | `ALL_TERMINAL done=1 isolated=0` → 下一步；其他情况 → 记录 `logs/<id>.log` 末尾，到实现步或到标“结束”的步并在报告写明环境不可用 |
| 实现（每个新增逻辑一步） | “按规格 §X 实现 …，然后运行 `python checks/fx_xxx.py`” | `OK` → 下一步；`MISMATCH` → 其他情况 |
| 启动 | `python run_units.py run --units units.jsonl --concurrency N --retries R --retry-sleep S --min-free-gb G --detach` | `LAUNCHED` → 等待步 |
| 等待 | `python run_units.py status --units units.jsonl --wait 540` | `RUNNING` → 等待步本身；`ALL_TERMINAL` → 汇总步；`RUNNER_STALE`、`NOT_RUNNING`、`NO_STATE` → 启动步 |
| 汇总 | 汇总脚本命令 | 产物文件存在 → 交付步 |
| 交付（标“结束”） | `python checks/deliverables.py` 打印 `OK` 或 `MISSING <文件>` | 两种输出都到此结束；MISSING 的文件在报告里列为缺项 |

上表中的 `<首个单元 id>`、N、R、S、G 由编写者填成实际值，交付的文件里不留尖括号。集群单元的 cmd 必须阻塞到作业结束；本机单元的并发与内存阈值写在启动命令里。检查嵌入步骤，一行一个检查；不单列审核、复核、验收步骤，不写“完成后汇报”。中间结果写“落盘并继续”，只有交付步写“交付”。

新增实现的目标函数、选样规则、统计口径由编写者定死，不借“工程自主”交给执行者。复用现成代码的步骤无需重写其内部实现。

### 5 交付清单

文件名与内容字段；`PROGRESS.md` 与 `runner_state.json`；每个单元的身份、完成情况与隔离原因（从状态文件导出）；要求的指标无结果写明缺项，不填零冒充。报告只写事实、数值与机械标签，不写科学结论，不写“全部通过”式总评。不要求证明流程完备的报告、全目录哈希、封印或独立复算，除非用户本批要求；技术正确性检查确为本批要求时写成步骤表里的一行。

## 规格文件

矩阵的组合规则、排除项与复用范围；固定的数据划分、模型、初值、种子、训练与评价步数、检查点规则，不允许看结果后更换。数学定义：变量、形状、单位、索引、取值集合、归一化分母、精度与容差；训练说明梯度、更新与冻结参数、优化器、随机流与恢复状态；新逻辑不以概念名或论文链接代替实现定义。指标：样本集合、分母、宏或微平均、配对、单位、缺失处理；结果标签只用于交付或预先定义的分支，不替代数值。NaN、缺测、空集合、未完成的数值处理规则写在这里，由单元脚本实现。新增逻辑的伪代码与小算例；随机流表。估计的耗时与资源量在这里标“估计”。数值只维护在这里，入口与步骤引用键名。

## 单元清单

units.jsonl 每行 `{"id": ..., "cmd": ..., "cwd": ..., "done_file": ..., "requires": [...]}`。id 由矩阵坐标拼成；cmd 是「环境与入口」里的启动命令加该单元的参数；done_file 是该单元最后写出的文件；requires 列出它读取的、由其他单元产出的文件。矩阵大时写 `make_units.py` 从规格展开，步骤表里先运行它（看什么：`units.jsonl` 行数等于规格给的单元数）再冒烟。字段含义与脚本行为见 [运行脚本说明](runner.md)。
